## Recovery bug discovered and fixed

The real DNS failure exposed a presentation bug: while the authoritative RPC read was unavailable, the selected-task badge could fall back to the stale Gateway inbox status and display `OPEN` even though state-changing actions were correctly locked.

Root cause:

`displayStatus` and `displayWorker` fell back to `selectedTask` Gateway data after the authoritative state was cleared at refresh start.

Fix:

- selected-task status and worker are presented only from authoritative Solana state;
- unavailable RPC produces unknown/unreconciled presentation instead of stale authoritative-looking state;
- state-changing actions remain fail-closed.

Regression cycle:

- RED run `36312405844`
- GREEN run `36312595528`
